# 后端为主的全栈验收场景矩阵

基线：`f206bcf6dff291d346cf5c3cf5a68bfce938935e`。共 84 项场景，全部初始状态为 **NOT_RUN**。它们是建议的最低验收基线，不是所有可能输入的穷尽证明。

每项在执行后必须补充：实际测试ID、命令、环境、候选SHA、退出码、断言摘要、报告路径、发现缺陷及重测记录。证据必须来自实际测试运行；此文件不授予生产操作权限。

## ENV｜环境与安全配置
| 编号 | 场景 | 给定 | 操作 | 必须观察到的结果 |
|---|---|---|---|---|
| ENV-01 | 生产安全开关真实生效 | 独立新库、生产候选配置和已知演示种子 | 启动应用并读取脱敏后的有效配置，再分别尝试演示与正式账号登录 | 严格生产检查已开启；演示账号不可登录；正式初始化账号可用；证据记录实际 profile，不以 env 文件文本代替 |
| ENV-02 | 不安全生产配置拒绝启动 | 严格生产模式 | 分别开启验证码调试、关闭 Secure Cookie、保留演示账号 | 每个不安全组合都启动失败并给出不含密钥的原因；测试组合不修改真实环境 |
| ENV-03 | 双层代理真实来源 | 隔离的 Caddy→Nginx→后端拓扑 | 从两个不同来源登录，并在测试请求中提供伪造转发头 | 来源区别可见；伪造前缀不改变客户端身份；两个来源不合并成代理容器 IP |

| ENV-06 | 干净检出可重复运行 | 未携带个人 .env、Cookie、原机产物的新工作区 | 按仓库脚本启动测试依赖并运行测试 | 依赖、端口、配置均可重建；mvnw 的 Docker 依赖与网络明确；不存在对原机隐藏文件的依赖 |

## AUTH｜登录、密码与会话
| 编号 | 场景 | 给定 | 操作 | 必须观察到的结果 |
|---|---|---|---|---|
| AUTH-01 | 首次改密服务端约束 | 新建必须改密的账号 | 登录后绕过页面直接调用业务写接口，再完成改密 | 改密前仅允许批准的安全端点；改密后取得正常权限；不能只依赖前端弹窗 |
| AUTH-02 | 会话撤销与索引过期 | 短 TTL、可控时钟、同一用户两端会话 | 推进时钟跨过用户会话索引寿命，使用仍存续会话后执行禁用/重置密码 | 所有被撤销会话立即失效；活跃续期不造成索引失联；服务端绝对有效期仍受限 |
| AUTH-03 | 学校与平台入口隔离 | 独立学校和平台会话，若引入 WIP 则采用统一新协议 | 交错登录、刷新、退出、打开多标签页 | 不同入口不会覆盖身份或串用组织；API、下载、进度订阅均遵守同一会话协议 |
| AUTH-04 | CSRF 正反向 | Cookie 认证的已登录用户 | 对新增、编辑、发布、上传、改密、退出分别发送缺失、错误、正确 CSRF 证据 | 不合法写请求被拒绝且无副作用；合法请求成功；未登录端点采用明确保护策略 |
| AUTH-05 | 并发登录与暴力尝试 | 同一账号及多个账号、隔离 Redis | 并发错误登录后正确登录，并重启或断开 Redis | 失败计数不丢失；响应不泄露账号详情；依赖故障按已定义策略失败且告警 |
| AUTH-06 | 临时密码与真实二次认证 | 账号初始化、密码重置、2FA 能力标记 | 读取账号状态并执行相应登录流程 | 临时密码不入日志且只按批准流程交付；未实现第二因素不得显示已启用；角色与改密标记不能充当 2FA 状态 |

## PERM｜权限与学校隔离
| 编号 | 场景 | 给定 | 操作 | 必须观察到的结果 |
|---|---|---|---|---|
| PERM-01 | 普通管理员跨校拒绝 | 学校 A/B 各有同名教师和不同任务 | A 管理员替换 URL、请求体、查询参数里的 B 学校资源 ID | 读取、写入、下载、导出均拒绝；B 数据不改变；不泄露存在性细节 |
| PERM-02 | 教师只操作本人 | 两名绑定账号的教师 | 教师 A 确认、拒绝、签到、标记已读本人及教师 B 的资源 | 本人合法操作成功；他人操作拒绝；教师不能查看全校不必要的个人信息 |
| PERM-03 | 只读角色全路径 | VIEWER 与普通管理员 | 分别执行所有业务 GET 和所有写方法 | 只读范围符合角色矩阵；禁止的 POST/PUT/PATCH/DELETE 无副作用；不能通过旧入口绕过 |
| PERM-04 | 批处理逐项授权 | 合法 ID 与跨校 ID 混合的批量请求 | 导入绑定、批量删除、通知、导出 | 按固定事务策略全拒绝或明确逐行拒绝；绝不悄悄处理越权元素 |
| PERM-05 | 租户停用和权限变更 | 多个活跃会话、正在轮询的任务 | 停用学校、降权账号并继续使用旧会话 | 规定窗口内所有请求按新权限执行；进度流不能继续泄露数据；恢复不复活旧凭据 |
| PERM-06 | 双层鉴权一致 | 控制器、SecurityFilterChain、业务服务和仓储 | 用真实登录会话覆盖关键端点 | URL 规则与方法权限不相互误拦；授权条件一致；测试不只 mock 掉安全过滤器 |

## SOLVE｜排班与算法正确性
| 编号 | 场景 | 给定 | 操作 | 必须观察到的结果 |
|---|---|---|---|---|
| SOLVE-01 | 岗位覆盖与资格 | 两间考场、不同主副监需求、至少一名不具备主监资格的教师 | 分别走旧任务、新计划及手动调整入口 | 人数精确覆盖；主监资格有效且未过期；无重复人次占位；不同入口执行相同约束 |
| SOLVE-02 | 跨任务时间和跨校区移动 | 同校两个活跃考试任务、区间重叠和相邻校区场次 | 依次和并发生成、调整排班 | 检查同校已生效占用，不只当前 run；区间按约定边界；移动时间足够；不重复计入历史无效版本 |
| SOLVE-03 | 反例：先排错人不等于无解 | 早场 08:00–09:00 与晚场 10:00–11:00 各需一名主监；A/B 都合格且每日最多一场；A 两场可用；B 晚场请假；A 编号排前 | 执行确定性分配 | 可行解为早 B、晚 A；先早 A 导致卡住属于搜索失败，不是业务证明无解；可回溯或交给完整求解器 |
| SOLVE-04 | 独立结果验证器 | 求解结果中分别注入缺岗、重复教师、资格无效、时段重叠、超容量 | 通过独立验证器与发布入口 | 每一项错误均被拒绝；验证器不简单复制求解器同一 helper；结果不可因算法返回 succeeded 就被信任 |
| SOLVE-05 | 硬软约束与公平口径 | 同次数不同长度考试、班主任上限、固定锁定岗位及稀缺人员 | 运行不同策略组合与不可满足组合 | 硬约束不自动降软；软约束有量化违反项；时长/次数/主监负担分别报告；不向用户宣称唯一最优 |
| SOLVE-06 | 整体预算与失败分类 | 模型无效、真正无解、预算耗尽和可行但未证最优的夹具 | 运行求解及重试 | 整体 deadline 覆盖重试；MODEL_INVALID、INFEASIBLE、UNKNOWN、FEASIBLE 明确区分；保留 seed/版本/输入哈希/耗时 |

| PUBLISH-02 | 审批职责分离 | 已提交审批方案及提交人、另一批准人 | 提交人自审、另一人审批、未审批发布 | 自审和跳过必需审批均被拒绝；合法审批可发布；如果产品允许简化流程须显式规则而非接口旁路 |
| PUBLISH-03 | 并发编辑防覆盖 | 两个管理员读取相同版本游标 | 同时修改同一排班并发布 | 只允许满足版本条件的事务提交；另一个收到冲突并保留输入；不存在半新半旧发布结果 |
| PUBLISH-04 | 发布幂等与事务事件 | 同一方案同一或不同请求重试 | 双击或并发发布，并注入提交失败 | 最终有效版本唯一；通知事件不重复；事务回滚不留下成功通知 |
| PUBLISH-05 | 已发布版本不可静默改变 | 已发布方案、已读教师和后续紧急替班 | 编辑、撤销、重做、创建后继版本 | 保持历史版本可核验；通过受控后继或变更流程生效并通知受影响教师；旧新页面同指向有效版本 |
| PUBLISH-06 | 完整考务闭环 | 新计划与旧任务适配数据 | 规划→校验→审批→发布→通知→本人确认/签到→应急处理→结束归档 | 每一步状态由真实副作用产生；归档不可错误回退；旧接口不能绕开新流程的强制约束 |

## ASYNC｜异步、恢复与资源控制
| 编号 | 场景 | 给定 | 操作 | 必须观察到的结果 |
|---|---|---|---|---|
| ASYNC-01 | 提交后进程中断 | 任务状态已持久化，尚未被执行器领取 | 在隔离测试中终止并恢复应用 | 任务可重新领取或明确失败；不会永久 QUEUED；结果和副作用幂等 |
| ASYNC-02 | 计算中进程中断 | 处于 RUNNING 的旧排班和新规划任务 | 终止 worker 后重启 | 租约/心跳或等价机制回收；失联任务可恢复；不继续占有永不释放的运行锁 |
| ASYNC-03 | 队列满载不拖垮应用 | 超过候选容量的并发排班请求 | 同时登录、查询、取消任务 | 按资源预算限流；不无限排队；请求线程不会不受限执行重计算；明确返回排队/繁忙状态 |
| ASYNC-04 | 真实取消 | 等待中与计算中任务 | 点击取消并重复请求 | 取消在规定窗口内生效；不只改页面；已取消结果不得晚到覆盖有效方案 |
| ASYNC-05 | SSE 重连与权限 | 运行任务、已登录用户及会话过期状态 | 断网重连、刷新、跨校订阅、过期会话继续读流 | 可恢复进度或受控轮询；终态不遗漏；越权和过期订阅失效；新会话头协议兼容实际浏览器能力 |
| ASYNC-06 | 依赖失效与多实例 | 数据库/Redis 短时不可用、两个 worker 同时领取 | 恢复服务并重试 | 状态可解释、有告警；不会双份生效；事务提交不确定时按幂等查询恢复而非盲目重做 |

## 状态与范围
`NOT_RUN`：尚未执行；`BLOCKED`：环境或授权阻断；`FAIL`：运行后不满足；`PASS`：在记录范围内实际通过。
外部邮件、短信或AI未获启用批准时，必须记录“未启用／未交付该能力”，只验收关闭路径，不能把真实外发场景标为PASS。任何从必需范围排除的功能须有用户认可的变更记录，不能由Codex静默降级。
新发现的控制器、定时任务、下载入口或跨模块路径应新增场景；不要为了保留当前数量而省略。
