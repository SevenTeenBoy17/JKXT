# 06 — 商业化 + 长期维护策略

## 1. 市场定位与画像

### 1.1 目标客户分层

| 层 | 规模 | 痛点 | 价值主张 |
|---|---|---|---|
| **个体教务老师**（小学/初中）| < 50 教师 | 手工 Excel 排，易出错 | 免费 SaaS 试用，3 分钟出表 |
| **中型 K-12 学校** | 50-300 教师 | 6 月 / 1 月集中考试期忙不过来 | Pro 套餐，AI 公平度 + 历史统计 |
| **大型学校 / 教育集团** | 300+ 教师 / 多校 | 多校统一管理 + 数据合规 | 私有化 + Enterprise + 白标 |
| **教育局 / 区教委** | 区域级 | 跨校统筹 / 数据上报 | 行业版（v2.0 后）|

### 1.2 用户旅程

```
教务主任手工 Excel 拖累   →   听说 / 同事推荐 / 抖音号广告
    ↓
官网试用（免费 Starter）→ 3 表上传 → 5 分钟出第一个排考结果（aha 时刻）
    ↓
本学期重复使用 2-3 次 → 转付费 Pro
    ↓
下学期续费 / 推荐 / 升级 Enterprise
```

## 2. 套餐与定价

| 套餐 | 价格 | 含 | 限制 |
|---|---|---|---|
| **Starter** | 免费 | 50 教师以下，6 次排考 / 学期，1 管理员，云端，社区支持 | 无 AI 策略，无私有化，水印导出 |
| **Pro** | ¥980 / 学期 / 校 | 300 教师以内，不限排考次数，5 管理员，全 6 策略 + NL，去水印，邮件客服 | 无私有化，无白标 |
| **Enterprise** | ¥2,980 / 学期 / 校 + ¥1,500 AI 强化包 | 不限教师，10 管理员，专属 AI 模型选项，优先客服，年度数据报告 | 无白标 |
| **私有化** | ¥30,000 一次性 + ¥6,000 / 年 | 部署到客户机房，所有 Enterprise 功能，3 年质保 | 客户自备 LLM API key |
| **白标 OEM** | 定制 | 经销商授权，定制 logo / 域名 / 颜色 | 至少 30 校起 |

### 2.1 定价心理学
- Starter 永久免费 → 拉新；3 表 + 一次排考用过就回不去
- Pro 单价 ¥980 ≈ 1 个老师 1 天工资 → 教务主任授权门槛低
- 私有化 ¥30k 是教育局采购可走"软件"科目 → 招标友好

## 3. Go-To-Market

### 3.1 阶段 1（首 3 月）：种子用户
- 3 试点学校（创始团队人脉），免费 + 深度反馈
- 公众号 + 知乎"教务主任的 Excel 噩梦"系列
- 教育博主合作（B 站、抖音）做演示视频

### 3.2 阶段 2（4-6 月）：付费转化
- 知乎 / 教师交流群投放
- 试用 → 付费转化率目标 15%
- 月活校 100，付费 15

### 3.3 阶段 3（6-12 月）：渠道
- 教师培训公司 / 学校 IT 集成商 OEM
- 教育展会（中国教育装备展）
- 教育局区域推广

### 3.4 阶段 4（12+ 月）：生态
- 开放 API 接入校园钉钉 / 企业微信
- 数据互通：教务系统（如方天云、希沃）合作
- AI 能力开放：监考排课算法作为微服务

## 5. 长期维护策略

### 5.1 版本节奏

| 节奏 | 内容 |
|---|---|
| **大版本**（每半年）| 跟随学制变化、新课标、AI 模型代际升级 |
| **中版本**（每季度）| 新功能、UX 重大优化 |
| **小版本**（每月）| Bug 修复、prompt 调优、新对接 |
| **热修**（按需）| 安全 / 高优先 bug 24 小时内 |

### 5.2 AI 模型独立可换（核心架构原则）

- **抽象层**：LiteLLM 统一接口（不写死 Claude 或 GPT）
- **配置**：`config/ai.yaml` 定义可选模型 + 默认
- **A/B**：每个 prompt 同时跑两个模型，记录哪个公平度高
- **降级**：成本敏感时自动切 Haiku / Qwen-Turbo

### 5.3 数据库演进

- **Alembic** 每个迁移有 up + down
- **零停机原则**：
  - 加列：直接加（向后兼容）
  - 改列：先加新列 → 双写期 → 切读 → 删旧列（3 个版本完成）
  - 删表：先停写 → 1 个版本观察 → 删
- **备份**：SaaS 每天全量 + 每小时 WAL；保留 30 天
- **私有化**：内置 `backup.sh` 脚本 + 客户自管理

### 5.4 文档与知识沉淀（compound engineering）

- 每个 sprint 结束后用 `ce-compound` 写一篇 `docs/solutions/<topic>.md`
- 季度用 `ce-compound-refresh` 整理过期内容
- 用户视角：`docs.ai-jianke.com` 持续更新 FAQ、最佳实践
- 内部：Notion + 飞书 wiki

### 5.5 安全与合规演进

| 时间点 | 行动 |
|---|---|
| 上线前 | OWASP Top 10 检查 + Bandit + ZAP 扫描 |
| 上线 3 月 | 第三方渗透测试 |
| 上线 6 月 | 等保 2.0 二级认证（教育行业刚需）|
| 12 月 | ISO 27001（如出海）|
| 数据 | 教育部数据本地化要求；私有化客户数据合同明确归属 |

### 5.6 可观测与运维

| 工具 | 用途 |
|---|---|
| **Sentry** | 错误聚合（前后端）|
| **Posthog** | 用户行为漏斗 |
| **Prometheus + Grafana** | API 延迟、Celery 队列、DB 慢查询、AI 调用量/成本 |
| **阿里云 ARMS** | 链路追踪（生产 SaaS）|
| **PagerDuty / 飞书机器人** | 告警（5xx 率 > 1% / 队列堆积 > 100）|

### 5.7 客户成功

- 每个付费校配置专属客服微信群
- 月度产品周报（新功能 + 路线图）
- 季度 NPS 调研
- 流失预警：连续 30 天无登录 → 主动联系
