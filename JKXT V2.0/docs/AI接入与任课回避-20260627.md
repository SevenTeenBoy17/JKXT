# AI 策略：接真实 LLM + 任课老师不监本班（2026-06-27）

## 1. 接入真实 LLM（当前批准的 OpenAI 兼容网关）
后端通过 `OpenAiCompatibleLlmClient` 调用 OpenAI Chat Completions 协议，使用 Bearer 鉴权、`response_format=json_object`、有界重试与主备端点轮转，并将 `choices[0].message.content` 按严格单一 JSON 对象解析为策略 DSL。私有栈无需改代码，只需在不入库的 `.env.private` 中配置环境变量后重启：

```
JKXT_LLM_ENABLED=true
JKXT_LLM_ACCEPTANCE_MODE=true
JKXT_LLM_PROVIDER=gpt-agent
JKXT_LLM_BASE_URL=https://api.llm-token.cn/v1
JKXT_LLM_FALLBACK_BASE_URL=https://gpt-agent.cc/v1
JKXT_LLM_API_KEY=sk-REPLACE_ME                  # 仅占位；真实密钥切勿提交进仓库
JKXT_LLM_MODEL=claude-sonnet-4-6
JKXT_LLM_MAX_RETRIES=2
```
重启：`docker compose -f docker-compose.private.yml --env-file .env.private up -d app`。

端点归一化规则：完整的 `.../v1/chat/completions` 原样使用；以 `/v1` 结尾的地址追加 `/chat/completions`；仅域名根地址追加 `/v1/chat/completions`。因此 `https://api.llm-token.cn`、`https://api.llm-token.cn/v1`、`https://gpt-agent.cc`、`https://gpt-agent.cc/v1` 以及完整 Chat Completions URL 都可被正确处理。当前默认主端点为低延迟的 `api.llm-token.cn/v1`；仅对 I/O/超时、HTTP 429 和 5xx 这类可重试故障轮转到 `gpt-agent.cc/v1`，随后在有界重试预算内回到主端点。其他 4xx 与响应 schema 错误直接失败，不盲目重试。

**验收模式**：`JKXT_LLM_ACCEPTANCE_MODE=true` 时，缺密钥、`provider=mock`、上游失败、空响应、Markdown/说明文字包裹、拼接多个 JSON 或 schema 不合格均 fail-closed，并返回稳定错误码，绝不会伪装为真实 AI 成功。非验收环境才允许返回确定性的安全策略草案，并如实标注 `status=fallback`。

## 2. 任课老师不监本班（subject_avoid，本轮新实装）
此前 AI 策略里的 subject_avoid 是 cosmetic（生成却被求解器忽略）。现已真实实装为**软偏好**：
- buildFixtureFromTask 读取 teacher_subject（教师任教学科）× school_class_subject（班级开设科目），为每位教师与每个考场（按所坐班级）计算学科集合。
- 求解器：当 policy.avoidSubjectClass 开启时，对"教师任教科目 ∩ 该考场班级开设科目 ≠ ∅"的分配加目标惩罚（权重与同年级同档，软项，绝不致无解）。
- 经 AI 策略 DSL 的 subject_avoid 规则 opt-in（如自然语言含"避开任教科目"或选择 subject_off 策略）；policyFromDsl 解析。
- 单元测试 AiPolicySolverTest.subjectAvoidSoftPrefersTeacherNotTeachingTheClassSubject 证明：两名教师除"是否任教该班科目"外完全等价时，求解器必选不任教者。

未实装：男女搭配（gender_mix，需按考场做性别均衡 reification，价值较低，留后续）。
