## 4. 正式登录与会话契约

### 4.1 登录接口

拟新增 `POST /api/v1/auth/school/login` 和 `POST /api/v1/auth/platform/login`。服务器从端点决定入口，不信任请求体中的 `role`、`orgId` 或 `audience` 来授予身份。

学校入口只允许数据库中有效、受支持的学校角色，明确排除 `SUPER_ADMIN` 和 `DEMO`；超管入口只允许当前有效的 `SUPER_ADMIN`。验证码、口令校验、账户锁定、IP 限流、机构状态及 private fixedOrg 校验仍然有效。

顺序：限流 → 验证码 → 凭据/账户有效性 → 入口匹配 → 机构和权限 → 创建对应用途会话 → 返回 Cookie。入口不匹配不签发、续期、撤销或替换已有合法会话，不写登录成功审计；返回 `403 AUTH_PORTAL_MISMATCH`。只有凭据验证后才返回入口提示，避免通过错误密码查询账号角色。

旧 `POST /auth/login` 兼容为 SCHOOL 登录，不能继续给超管签发不带用途的会话。旧客户端的超管登录须迁移到专用端点并得到明确说明。请求参数不能复活旧路径。

### 4.2 会话选择与权限

三种用途：`SCHOOL`、`PLATFORM`、`DEMO`。会话由服务端保存 `userId/orgId/audience/authVersion`；演示另有 `workspaceId/generation/expiresAt`。身份本身始终来自服务端，客户端字段仅用于选择入口。

- 正式环境分别使用 `JKXT_SCHOOL_SESSION`、`JKXT_PLATFORM_SESSION`；演示使用 `JKXT_DEMO_SESSION`。生产配置采用对应 `__Host-` 名称、HTTPS、`Secure`、`HttpOnly`、`Path=/`、不设置 `Domain`。本地 HTTP 环境使用不带 `__Host-` 的名称，禁止带入生产。
- 同主机不同端口不隔离 Cookie。独立名称、用途校验和存储隔离仍必须实现；生产演示站另使用独立 origin。
- 生产演示站还必须与正式站使用不同 hostname，并使用 host-only Cookie；只有换端口不满足生产隔离。本机多端口仅用于受控测试，不冒充生产浏览器安全边界。SCHOOL / PLATFORM 的入口与会话隔离不等于隔离同源 XSS，仍须保留独立的内容安全与脚本注入防护验收。
- 保留现有业务 URI 时，正式 API 使用明确的 `X-JKXT-Portal: school|platform` 选择对应 Cookie；该字段不是授权凭证。缺省只选 SCHOOL，未知值拒绝，绝不自动挑选“权限更高”的 Cookie。
- 选择 PLATFORM 仍须验证该 Cookie 确属 PLATFORM、当前账户仍为超管，并继续执行现有路由/能力/租户授权。正式实例完全不接受 DEMO 身份。
- `/admin/**` 仅接受 PLATFORM 超管会话。超管既有代管学校业务能力保留在 PLATFORM 用途中，不借此赋予学校用户平台权限。
- 原 `JKXT_SESSION` 不用于新入口恢复。升级时旧会话失效并要求重新登录；不能按旧快照无感提升为新用途。
- `/auth/me`、退出、密码变更均使用明确用途；响应中返回服务端确认的用途和能力，前端必须验证后挂载对应外壳。
- 正式登录与 `/auth/me` 同时返回用途绑定的 CSRF token，并设置 `Cache-Control: no-store`；前端仅按用途/身份保存在内存。新登录、改密或明确安全轮换后旧 token 失效，不能将学校 token 用于平台会话，也不放入 URL 或持久化日志。
- 登录和 `/auth/me` 返回不具备单独登录能力的 `sessionContext`；业务请求携带 `X-JKXT-Session-Context`，必须与所选 Cookie 的当前会话一致。缺失或不匹配返回 `409 SESSION_CONTEXT_CHANGED` 并中止业务；不把它当备用令牌。首次会话发现仅限 `/auth/me`。同入口成功重登后撤销旧会话并签发新上下文；错误入口和失败登录不撤销已有会话。此约束覆盖写入、敏感读取与导出，防止旧标签页拿新 Cookie 操作新账号。
- 每次受保护请求验证账户/机构状态与授权版本，禁用、降权、密码重置后旧权限快照不可继续写。密码修改撤销其他会话，并测试两个正式入口的失效契约。
- 退出只撤销该入口会话并清除对应 Cookie；退出请求失败不能显示“已安全退出”，应提示重试且停止继续展示敏感页面。
- 业务缓存/记住账号键以环境、用途、机构、用户组成命名空间；切换身份清理状态、取消请求、关闭 SSE/WS。旧请求返回前再次核对身份代次。

### 4.3 CSRF、跨站与错误

不能因为当前代码关闭 CSRF 就继续忽略 Cookie 写接口风险。正式登录需校验允许的 Origin、JSON Content-Type 和验证码；浏览器缺失/不可信 Origin 的登录写请求拒绝。认证后的写操作需会话绑定 CSRF token；前端通过约定 header 发送，服务端验证，不能只靠 SameSite。

演示站与正式站不互相放开凭据 CORS；允许来源精确配置，不使用凭据加任意 origin。WebSocket 验证 Origin 与用途，SSE/下载同样受身份保护。错误沿用统一响应结构及 traceId，日志不得包含口令、验证码答案、Cookie 或上传教师个人信息。

不能假设原生下载链接、EventSource 或 WebSocket 会发送自定义 header。下载使用带上述身份上下文的受控 fetch 后生成临时下载对象；SSE 如存在则改用带 header 的 fetch stream。WebSocket 如存在，须先经受保护接口获取单次、短时、绑定会话/用途/工作区代次的握手票据，建连后仍检查撤销和到期。不得在 URL 放长期会话令牌，不得为这些通道回退挑选其他入口 Cookie；实现计划须先确认实际存在的通道，未使用的通道不新增。

长连接每次发送业务事件/下载数据块前复核会话和工作区有效性，禁用、重置、到期后终止旧流；不能只在建连时鉴权。取消前端请求不能阻止浏览器处理晚到的 `Set-Cookie`：服务端必须拒绝被旧响应覆盖回来的已撤销会话，前端显示身份已变化并重新确认当前入口，不能回退到旧账户。已经发送的字节、用户已保存的文件不在可撤回范围内。

## 5. 演示沙盒设计

### 5.1 环境隔离

新增独立演示部署配置，使用独立数据库、独立 Redis 和上传/导出存储目录或桶，数据库凭据无权访问正式库。正式 private 实例与 fixedOrg 设置保持不动。

演示实例允许多个演示工作区：采用已有租户隔离模型，每位访客对应服务端创建的演示机构和受限 `DEMO` 身份。实例内只能存在 `purpose=demo` 工作区；不能通过传入正式机构 UUID 选择学校。不得直接将普通 ADMIN 种子账号公开给访客。

拟新增显式 `demo` 部署模式，仅演示实例启用；不能把正式 private 改成 dev/saas 来绕过固定机构约束。模式、DEMO 角色、数据库合法值约束、能力映射与启动保护须一起评审；正式实例禁用演示签发端点。演示实例只从当前 DEMO 会话推导机构，永不信任客户端租户选择头。

生产启动检查必须拒绝演示配置指向正式连接、存储或 Cookie 用途的配置；不能把“名字不同”当隔离充分证据。隔离验收还要核对实际数据库/Redis连接标识、凭据权限、文件根目录和写入指纹。演示实例默认没有正式 AI、短信、邮件、Webhook、平台管理密钥；并阻止对应出口。

### 5.2 一键创建、恢复与重置

拟定演示接口仅在演示实例提供：

- `POST /api/v1/demo/visitor`：通过 Origin/JSON/滥用保护建立短期、无业务权限的服务端访客会话，返回 host-only、HttpOnly 的独立访客 Cookie 和与其绑定的启动上下文；已有有效访客会话时复用。此端点不创建学校数据。
- `POST /api/v1/demo/sessions`：无账号密码；验证访客 Cookie、启动上下文及 Origin 后创建或恢复该访客唯一的活跃工作区。身份、角色、机构和工作区 ID 均由服务端生成，不接受客户端指定归属。返回 DEMO Cookie、CSRF token、能力、到期时间及明确的演示标志。
- `POST /api/v1/demo/workspace/reset`：已认证、CSRF 校验、二次确认后重置当前访客工作区，不接收任意机构 ID。
- `/auth/me` 与 `/auth/logout`：演示用途版本，只作用于当前 DEMO 会话，不读取正式 Cookie。

首次创建使用访客会话下的幂等键与服务端事务/资源预留：幂等记录绑定访客、操作类型及参数摘要，重放不得绕过归属鉴权；同时以唯一约束限制每位访客一个活跃工作区。部分初始化失败清理已预留资源并返回错误，不把缺数据工作台当成功。前端不得生成未验证的本地“已登录”状态。

访客以服务端已建立的演示访客会话为边界，复制标签页或再次点击按钮只恢复同一工作区，不生成第二位访客。前端通过演示 origin 内的跨标签互斥协调串行执行访客引导，等待访客 Cookie 生效和上下文确认后才创建工作区；该浏览器能力不可用时明确限制为单标签引导，不声称已完成无条件跨标签去重。无法建立共享 Cookie 的独立首访不保证属于同一访客；弃置的未完成预留受短期过期清理约束。

只有显式重置、有效期届满后重新进入或使用另一浏览器配置文件才产生新数据代次/访客。恢复已有工作区不消耗新建配额；新访客/新工作区分配计入配额，所有引导请求仍受请求速率限制；更换幂等键不绕过实例/IP 配额。

重置将旧 generation 失效并创建新的数据代次；数据库写入、求解任务持久化、下载读取都必须校验工作区状态和代次。正在运行的旧作业停止或丢弃结果，不能在重置后把旧数据写回。失败时显示明确状态，允许幂等重试，不静默重置其他访客。

重置按当前工作区、旧 generation 与幂等操作标识做原子比较更新。重复请求返回同一操作结果，不连续清空新代次。状态明确区分 READY / RESETTING / FAILED / EXPIRED：重置一开始旧代次即禁止新访问，成功初始化后才开放新代次，失败保持不可用并提供该操作的重试；不得因一次失败恢复旧代次访问。写入和任务提交在同一受控提交边界复核 generation、状态和服务端期限，不只在请求入口检查。已传到浏览器或已导出的内容无法事后收回，应如实区分与“旧链接不能再下载”。

重置更新服务端会话所指的 generation、sessionContext 和 CSRF token，不通过重置响应重新写会话 Cookie；常规恢复请求也不重复写旧 Cookie。客户端只接受当前重置操作的最新上下文。EXPIRED 是该工作区的终态，过期优先于初始化或重置完成，重试不能将其恢复为 READY；只能经重新进入创建新的工作区。晚到的初始签发 Cookie 若已被撤销或已到期，服务端拒绝，并提供重新进入提示，不能重新激活旧工作区。

### 5.3 演示能力白名单

允许：演示教师/班级/科目/考场数据查看与编辑；使用模板或脱敏 Excel 导入；任务校验；规则选择；实际本地求解；人工调整与冲突提示；工作区内结果保存；带演示水印的导出；明确标识的模拟发布。

拒绝：平台管理、跨租户切换、真实用户/口令/密钥管理、真实审批身份冒充、真实教师通知、对外 Webhook、收费模型调用、正式发布、任意URL导入和跨工作区文件访问。

`DEMO` 角色只获得上述业务所需能力，并由独立服务端 route/method 白名单进一步限制。新增业务路由默认不开放给演示，不把角色改成 ADMIN 以通过兜底规则。凡允许的按钮必须对接真实沙盒操作，不能以一个 toast 代替结果。

Excel 导入先完成全量校验再提交同一批次；有错误时显示具体行号、字段和原因，不悄悄形成部分导入。修正后重试须幂等。人工调整需持久化、刷新回读；导出携带任务修订与演示标识，反读 XLSX/PDF 时与该修订逐项比对，已过时的导出明确显示旧版本，不能冒充最新排班。

外部自然语言 AI 默认不可用并如实标注；规则配置和 OR-Tools 求解仍可真实运行。样例策略可作为教学输入，但必须注明预置示例，不冒充实时大模型调用。

### 5.4 数据与生命周期默认值

下列为本规格建议默认值，均受服务端限制，需随规格确认：

- 初始化 120 名完全合成教师，包含班主任、主/副监考资格、学科、不可用时段等；配套考试和考场，展示合理中文名称。不得复制正式学校个人数据。
- 活跃会话空闲 30 分钟失效，工作区创建后绝对 2 小时失效；频繁请求不能无限延长绝对期限。
- 空闲续期仅由明确的用户操作驱动，后台轮询、SSE 保活和静态资源加载不续期；重置不延长原工作区的绝对期限。过期判断以服务端时间为准，提交边界到期的业务写入拒绝，旧下载链接和未完成作业同时失效。
- 每工作区最多 150 名教师、40 个考场、100 场考试；上传文件上限 10 MiB，并另做压缩展开大小、工作表/行数和类型校验。
- 同工作区至多 1 个求解作业并行，单作业预算 30 秒；超限需明确提示，不假报完成。实例活跃工作区上限 20，超过返回可重试繁忙状态。
- 演示启动每 IP 每 10 分钟最多 5 次；反代 IP 仅信任配置的代理。重置、上传、求解另设频率与并发限额，不能靠更换幂等键绕过。
- 过期立即拒绝访问；清理程序目标 15 分钟内删除该工作区业务数据与文件，失败记录并重试。实例重启后继续清理，不仅依赖进程内定时器。
- 演示资料明确提示“仅上传模拟或脱敏数据”；导出名称、表格说明和打印输出标明模拟数据及工作区代次，不能混入正式统计。
